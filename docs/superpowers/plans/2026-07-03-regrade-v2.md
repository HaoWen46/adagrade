# Regrade v2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: superpowers:subagent-driven-development. Normative spec: [`2026-07-03-regrade-v2-design.md`](../specs/2026-07-03-regrade-v2-design.md) (D54–D62) — behavior questions are answered there by section number. This REPLACES the v1 regrade flow (pre-production; no compatibility shims).

**Goal:** Multi-problem `<pN>` requests, single-use per-turn token chain, per-problem verdicts with a hard-gated TA-clicked result email, final-turn TA handoff, unparsed-row reminders.

## Global Constraints

Unchanged house rules (test-first; no PII in logs/fixtures — complaint text and TA-notify bodies are PII; explicit-path `git add`; never repo-wide test runs while parallel agents run; money/points decimal strings; F17 on any queue work). Migration number assigned: `0025_regrade_v2.sql`. Only Task W1 runs `make sqlc` until it lands. The v1 inbound heuristic (`internal/regrade/match.go` in the webhook path), `escalated` band, `HARD_MAX`, single `problem_id`/`ai_record_id` request columns, and `POST /api/regrades/{id}/resolve` are all REMOVED — update/replace their tests, never weaken assertions that still apply.
